# 사용 방법

이 프로그램은 내 컴퓨터에서 대한항공의 공개 보너스 좌석 현황을 조회하고, 원하는 날짜를 공식 화면에서 다시 확인할 수 있도록 돕습니다.

## 1. 처음 설치하기

Windows 11 이상 또는 macOS 14 이상에서 사용하도록 구성되어 있습니다. Python 3.8 이상, Node.js 22 이상과 Google Chrome이 필요하며, 새로 설치할 때는 Python 3.11 이상을 권장합니다. Linux는 미검증입니다.

### Windows: 더블클릭으로 설치하기

1. [Python 공식 다운로드](https://www.python.org/downloads/windows/)에서 Python을 설치합니다. **Add python.exe to PATH** 항목이 있으면 선택하세요.
2. [Node.js 공식 다운로드](https://nodejs.org/en/download)에서 22 이상의 버전을 설치합니다. npm도 함께 설치됩니다.
3. [Google Chrome](https://www.google.com/chrome/)을 설치합니다.
4. GitHub에서 받은 ZIP 파일을 **압축 해제**합니다. ZIP 미리보기 안에서 실행하지 마세요.
5. 프로젝트 폴더의 **`setup-windows.bat`**를 더블클릭합니다.

설치 파일은 Python과 Node.js를 확인한 다음 `npm ci`로 **Playwright를 포함한 프로젝트 의존성**을 설치하고 Chrome 실행 여부를 확인합니다. Python·Node.js·Chrome 자체를 대신 설치하거나 관리자 권한을 요청하는 파일은 아닙니다. 없는 프로그램이 있으면 안내에 따라 설치한 뒤 다시 실행하세요.

Windows PowerShell에서 직접 설치하는 방법도 있습니다.

```powershell
python --version
node --version
npm.cmd ci
npm.cmd run doctor
```

`python` 명령을 찾지 못하지만 Python 런처가 설치되어 있다면 `py -3 --version`을 사용하세요. Python이나 Node.js를 설치한 직후에는 터미널을 닫고 새로 열어야 경로가 반영될 수 있습니다.

### macOS: 터미널에서 설치하기

GitHub에서 프로젝트를 받은 뒤, 터미널에서 `package.json`과 `local_app.py`가 있는 폴더를 엽니다. 버전은 다음 명령으로 확인할 수 있습니다.

```sh
python3 --version
node --version
npm --version
```

명령을 찾을 수 없다는 메시지가 나오면 해당 프로그램을 설치하고 터미널을 다시 열어 주세요. 준비가 끝나면 프로젝트 의존성을 설치합니다.

```sh
npm ci
npm run doctor
```

대한항공 계정, API 키, 카카오 개발자 계정, 메일 설정은 필요하지 않습니다. `.env` 파일을 만들거나 Python 패키지를 별도로 설치할 필요도 없습니다.

### Playwright와 브라우저 설치의 차이

이 프로젝트의 Playwright는 Node.js 패키지이므로 `npm ci`로 설치됩니다. Python용 Playwright를 추가로 설치할 필요가 없습니다.

실제 자동 입력에는 컴퓨터에 설치된 Google Chrome을 사용합니다. Chrome을 공식 설치 프로그램으로 준비했다면 별도의 Playwright 브라우저 다운로드 명령은 필요하지 않습니다. [공식 Chrome 사용 안내](https://playwright.dev/docs/browsers#google-chrome--microsoft-edge)

`npm run doctor`는 Python·Node.js·Playwright·Chrome을 확인합니다. 설치만 다시 확인하려면 Windows에서 `setup-windows.bat --check`를 실행해도 됩니다. 이 검사는 대한항공 조회를 실행하지 않습니다.

## 2. 조회 화면 실행하기

**Windows:** 프로젝트 폴더의 **`start-windows.bat`**를 더블클릭합니다. PowerShell에서는 다음 명령을 사용해도 됩니다.

```powershell
python local_app.py --open
```

Python 런처를 이용하려면 `py -3 local_app.py --open`으로 실행합니다.

**macOS:** 다음 명령을 사용합니다.

```sh
python3 local_app.py --open
```

[로컬 조회 화면](http://127.0.0.1:8765/)이 열립니다. 주소가 열리지 않으면 실행한 터미널에 오류가 있는지 확인하세요. 터미널은 프로그램을 사용하는 동안 열어 둡니다.

macOS에서는 최초 설치를 마친 후 프로젝트 폴더의 **`마일리지 조회.command`**를 더블클릭할 수도 있습니다. 더블클릭 실행 중 Python이나 Node.js를 찾지 못하면, 설치할 때 사용한 터미널에서 위 명령으로 실행하세요.

종료하려면 실행 중인 터미널에서 `Ctrl+C`를 누릅니다. 브라우저 탭만 닫으면 로컬 서버는 계속 실행됩니다.

### 기본 포트가 사용 중일 때

이미 실행한 프로그램이 있다면 기존 [조회 화면](http://127.0.0.1:8765/)을 사용하면 됩니다. 다른 프로그램이 같은 포트를 사용 중이라면 다음처럼 바꿉니다.

```sh
python3 local_app.py --port 8766 --open
```

이때 접속 주소는 [127.0.0.1:8766](http://127.0.0.1:8766/)입니다.

Windows에서는 `python local_app.py --port 8766 --open` 또는 `start-windows.bat --port 8766`을 사용합니다.

## 3. 편도 좌석 조회하기

예를 들어 인천에서 싱가포르로 가는 비즈니스 좌석을 찾으려면 다음과 같이 입력합니다.

| 입력 항목 | 선택할 값 |
| --- | --- |
| 여정 | 편도 |
| 출발 공항 | `ICN` |
| 도착 공항 | `SIN` |
| 가는 달 | 화면에서 선택 가능한 원하는 월 |
| 좌석 등급 | 비즈니스(프레스티지석) |

**마일리지 좌석 조회**를 누르면 해당 조건에 맞는 날짜를 표시합니다. 이전에 조회한 기록이 없거나 오래된 경우에는 조회용 Chrome 창이 열려 공식 화면을 확인합니다. 조회가 끝날 때까지 창을 조작하지 말고 기다려 주세요. 조회용 창은 작업이 끝나면 닫힙니다.

**가는 달·오는 달 목록은 연도별로 구분되어 있습니다.** 예를 들어 2027년 1월을 조회하려면 목록의 `2027년` 아래에서 `2027년 1월`을 고르면 됩니다. 조회 가능한 시작 월과 마지막 월은 입력란 아래에서 확인할 수 있습니다. 2026년 9월 7일 기준으로는 2026년 10월부터 2027년 8월까지입니다. 프로그램은 한 달 전체 현황을 확인하므로, 향후 360일 범위에 일부 날짜만 포함되는 마지막 달은 선택 목록에서 제외합니다.

날짜 카드에는 마일리지로 예약하는 **보너스 좌석 표시**가 있는 날만 나옵니다. 좌석 승급 표시는 포함하지 않습니다. 이 입력 예시는 사용법을 설명하기 위한 것으로, 특정 날짜의 좌석을 보장하지 않습니다.

### 여러 좌석 등급을 함께 보기

좌석 등급에서 **전체**를 선택하면 일반석·프리미엄석·비즈니스 중 하나라도 보너스 좌석 표시가 있는 날짜를 모아 보여줍니다. 날짜마다 표시가 있는 등급을 적어 두므로 어떤 좌석인지 구분할 수 있습니다. 한 날짜에 여러 등급이 있어도 날짜 수는 한 번만 계산합니다.

전체에는 **일등석과 좌석 승급을 포함하지 않습니다.** 일등석은 공개 화면에서 보너스와 승급이 함께 표시되어 구분할 수 없기 때문입니다. 좌석 등급을 바꾸는 것만으로는 새 항공사 조회를 보내지 않으며, 저장된 같은 달력에서 해당 날짜를 골라 보여줍니다.

왕복에서 전체를 선택하면 가는 편과 오는 편에 표시된 등급이 서로 다를 수 있습니다. 두 방향의 날짜 카드에 적힌 등급을 각각 확인하세요.

### 자주 쓰는 공항 코드

| 공항 | 코드 | 공항 | 코드 |
| --- | --- | --- | --- |
| 서울/인천 | `ICN` | 싱가포르/창이 | `SIN` |
| 서울/김포 | `GMP` | 도쿄/나리타 | `NRT` |
| 부산/김해 | `PUS` | 도쿄/하네다 | `HND` |
| 뉴욕/존 F. 케네디 | `JFK` | 로스앤젤레스 | `LAX` |
| 파리/샤를 드골 | `CDG` | 런던/히스로 | `LHR` |

도시 이름 대신 공항의 영문 세 글자 코드를 입력하세요. 출발지와 도착지는 서로 달라야 합니다. 코드가 유효해도 대한항공 공개 달력에서 해당 노선을 제공하지 않으면 조회되지 않을 수 있습니다.

## 4. 왕복 좌석 조회하기

1. **왕복**을 선택합니다.
2. 출발·도착 공항과 **가는 달**, **오는 달**, **좌석 등급**을 입력합니다. 가는 달과 오는 달은 같아도 됩니다.
3. **마일리지 좌석 조회**를 누릅니다.
4. 가는 편 결과에서 날짜를 먼저 고릅니다.
5. 오는 편 결과에서 돌아올 날짜를 고릅니다.

오는 편은 출발·도착 공항을 반대로 조회합니다. 예를 들어 가는 편이 `ICN → SIN`이면 오는 편은 `SIN → ICN`입니다.

가는 달을 바꿔서 기존 오는 달이 가는 달보다 앞서게 되면 오는 달을 같은 월로 맞춥니다. 이미 가는 달 이후로 선택한 오는 달은 그대로 유지합니다.

‘최소 여행 기간(일)’을 조절하면 **가는 편과 오는 편의 출발일 간격**이 그 이상인 날짜만 남습니다. 예를 들어 가는 편 출발일이 5일이고 값을 7로 설정하면 오는 편 출발일이 12일 이후인 후보를 보여줍니다. 현지 도착일이나 시차를 반영한 숙박 일수 계산은 아닙니다.

가는 날을 바꾸거나 최소 여행 기간을 늘려 기존 오는 날이 조건에 맞지 않게 되면, 오는 날을 다시 선택해야 합니다.

## 5. 선택한 날짜를 대한항공에서 확인하기

원하는 날짜를 고른 뒤 하단의 **선택한 날짜로 대한항공 열기**를 누릅니다. 왕복은 가는 날과 오는 날을 모두 선택해야 버튼이 활성화됩니다.

프로그램은 새 Chrome 창에서 다음 항목을 자동으로 입력합니다.

| 항목 | 적용되는 위치 |
| --- | --- |
| 출발·도착 공항, 편도·왕복 | 대한항공 보너스 좌석 조회 화면 |
| 가는 달·오는 달 | 탑승월 선택 화면 |
| 좌석 등급 | 달력의 보너스 좌석 필터 |
| 선택한 날짜 | 공개 달력의 날짜 선택 영역 |

전체를 선택한 경우에는 일반석·프리미엄석·프레스티지석의 보너스 필터를 함께 켭니다. 일등석·좌석 승급 필터는 끕니다.

로컬 화면에 완료 안내가 나타나면 열린 Chrome 창을 직접 사용하면 됩니다. 조회용 창과 달리, 이 창은 사용자가 확인할 수 있도록 열린 상태로 유지됩니다.

기존에 로그인해 둔 Chrome 창과는 별도 세션입니다. 로그인·예약·결제는 자동으로 진행되지 않습니다. 이후 예매 과정에서 로그인이나 조건 선택이 필요하면 대한항공 화면에서 직접 진행하세요.

결과 위쪽의 **대한항공 홈페이지 ↗**는 공통 조회 화면을 여는 일반 링크입니다. 선택한 값을 자동으로 넣으려면 하단의 **선택한 날짜로 대한항공 열기** 버튼을 사용하세요.

## 6. 저장된 결과와 기준 시각 이해하기

화면을 열거나 검색 조건을 바꾸면 **내 컴퓨터에 저장된 결과만** 확인합니다. 새로운 설치에서는 ‘아직 조회한 결과가 없어요’가 나오는 것이 정상입니다. 조회 버튼을 눌러 첫 결과를 가져와 주세요.

조회 버튼을 눌러도 최근 12시간 이내 결과가 있으면 이를 재사용합니다. 왕복에서는 가는 편과 오는 편을 따로 판단하므로 한쪽은 저장된 결과, 다른 한쪽은 새로 조회한 결과일 수 있습니다. 좌석 등급을 바꾸면 저장된 같은 달력에서 해당 등급의 날짜를 골라 보여줍니다.

| 화면 표시 | 뜻 |
| --- | --- |
| 좌석 표시가 있는 날짜 | 선택한 등급의 보너스 좌석 표시가 있는 날짜 수. 조회한 전체 날짜 수와는 다름 |
| 이달의 31일 전체 현황 확인 | 해당 월의 모든 날짜를 확인했다는 뜻. 날짜 수는 선택한 월에 따라 다름 |
| 여행 기간에 맞는 날짜 | 왕복 오는 편에서 가는 날과 최소 여행 기간을 적용한 날짜 수 |
| 좌석 현황 미확인 | 조회하지 않았거나 조회를 완료하지 못해 좌석 유무를 알 수 없는 상태 |
| 대한항공 공개 현황 기준 | 공식 화면에서 밝힌 좌석 현황의 기준 시각 |
| 현황을 가져온 시각 | 프로그램이 그 현황을 가져온 시각. 한국 시간으로 표시 |
| 이번에 가져온 결과 | 이번 조회에서 새로 가져온 해당 구간의 결과 |
| 이전에 가져온 결과 | 이전 조회 결과를 불러온 상태 |
| 오래된 결과 · 다시 조회해 주세요 | 프로그램의 재사용 기준보다 오래된 결과 |

**`0일`은 조회 실패 표시가 아닙니다.** 예를 들어 ‘31일 전체 현황 확인 · 프레스티지석 보너스 표시 0일’은 31일을 모두 확인했지만 공개 현황에 그 등급의 보너스 표시가 없었다는 뜻입니다. 실시간 매진을 확정한 결과는 아닙니다. 조회가 실패하면 별도의 오류 안내가 나오며, 표시할 결과가 없는 구간은 `0일` 대신 `—`와 `좌석 현황 미확인`으로 표시합니다.

새로 가져온 결과라도 대한항공 정보 기준이 실시간으로 바뀌는 것은 아닙니다. 공개 달력에 보너스 표시가 있어도 예약 가능 여부와 잔여 좌석은 예매 과정에서 다시 확인해야 합니다.

**선택한 날짜로 대한항공 열기**는 저장된 결과를 표시하는 동작과 다릅니다. 이 버튼은 누를 때마다 새 공식 창을 열어 선택한 조건을 입력하며, 로컬 조회 결과를 갱신하지는 않습니다.

## 7. 문제가 생겼을 때

| 상황 | 확인할 내용 |
| --- | --- |
| 로컬 주소가 열리지 않아요 | 실행 터미널이 열려 있는지, 표시된 주소와 포트가 맞는지 확인합니다. |
| `python3`, `node`, `npm` 명령을 찾지 못해요 | 필요한 프로그램을 설치한 뒤 터미널을 다시 엽니다. 설치를 확인한 같은 터미널에서 실행합니다. |
| `npm ci`가 실패해요 | 프로젝트 폴더인지, Node.js가 22 이상인지, 네트워크가 연결되어 있는지 확인합니다. |
| PowerShell에서 `npm.ps1`을 실행할 수 없다고 나와요 | `npm.cmd ci`, `npm.cmd run doctor`를 사용하거나 `.bat` 파일을 실행합니다. 실행 정책을 바꿀 필요는 없습니다. |
| Playwright가 없다고 나와요 | Windows는 `setup-windows.bat`, macOS는 `npm ci`를 실행합니다. Python용 패키지 설치로 대신할 수 없습니다. |
| Chrome을 실행하지 못했다고 나와요 | Google Chrome 설치 여부를 확인하고 `npm run doctor`로 점검합니다. 회사 PC에서는 브라우저 실행 정책의 영향을 받을 수 있습니다. |
| 자동 입력에 필요한 도구가 없다고 나와요 | 프로젝트 폴더에서 `npm ci`를 실행하고 Google Chrome 설치 여부를 확인합니다. |
| 처음 열었는데 결과가 없어요 | 새 설치에는 조회 기록이 없습니다. 조건을 입력하고 조회 버튼을 누릅니다. |
| 이번 달이나 먼 미래의 월을 선택할 수 없어요 | 이번 달은 지원하지 않습니다. 향후 360일 안에 월 전체가 포함되는 범위만 선택할 수 있습니다. |
| 다음 해의 월은 어디서 고르나요? | 가는 달·오는 달 목록에서 다음 연도 아래의 원하는 월을 선택합니다. 오래된 달력 화면이 보이면 최신 버전을 받은 뒤 페이지를 새로고침하세요. |
| 왕복의 오는 날이 보이지 않아요 | 가는 날을 먼저 선택하고 최소 여행 기간을 확인합니다. 조건에 맞는 공개 보너스 표시가 없을 수도 있습니다. |
| 대한항공 열기 버튼이 비활성화돼 있어요 | 날짜를 선택했는지 확인합니다. 왕복은 두 날짜 모두 필요하며, 다른 작업이 진행 중이면 완료까지 기다립니다. |
| 같은 결과가 계속 보여요 | 최근 12시간 이내 결과는 재사용합니다. 결과 아래의 두 기준 시각을 확인합니다. |
| 공항·월·필터·날짜를 입력하지 못했다고 나와요 | 입력한 조건과 Chrome 설치를 확인합니다. 사이트 화면이 바뀌었거나 응답하지 않는 경우에도 중단됩니다. 오류는 좌석이 없다는 뜻이 아닙니다. |
| 접속 제한이나 보안 확인 안내가 나와요 | 자동 처리가 중단된 상태입니다. 저장된 결과를 보거나 대한항공 공식 화면에서 직접 확인합니다. |

접근 제한 상태는 로컬 파일에도 저장되므로 프로그램을 껐다 켜도 자동 조회·자동 입력이 다시 시작되지 않습니다. 제한 상태 파일을 지우거나 헤더·쿠키·프록시를 바꾸는 방법을 재시도 절차로 사용하지 마세요.

구조 변경 등의 오류가 계속되면 오류 문구와 어떤 입력 조건에서 발생했는지 확인해 주세요. 진단 자료가 생성된 경우 `artifacts/airline-handoff/`에 남습니다. 자료에는 선택한 노선과 날짜가 포함될 수 있으므로 공유 전에 내용을 확인하세요.

## 8. GitHub에 포함되는 내용

프로그램 코드와 문서가 공유됩니다. `.gitignore`에 등록된 조회 결과·진단 자료·인증 정보·의존성 폴더는 포함되지 않습니다.

- `data/local/`: 내 컴퓨터에서 조회한 결과와 접근 제한 상태
- `artifacts/`: 개발·오류 확인용 자료
- `node_modules/`: `npm ci`로 다시 설치하는 의존성
- `.env`, 인증 세션 파일, 로그: Git 제외 대상

저장소를 다른 컴퓨터에 받으면 그 컴퓨터에서 설치하고 실행한 뒤 직접 조회하면 됩니다. GitHub에 코드를 올리는 것만으로 웹서비스가 배포되거나 카카오톡·이메일 알림이 작동하지는 않습니다.

GitHub Actions에서 Windows·macOS의 설치·자동 테스트·타입 검사·빌드가 모두 통과했습니다. [검사 결과](https://github.com/we-insub/Korean_air/actions/runs/34083177862)를 확인할 수 있습니다. 자동 테스트는 항공사에 접속하지 않으며, 실제 대한항공 조회까지 직접 확인한 환경은 macOS입니다. Windows 실기기에서의 항공사 조회는 아직 검증하지 않았습니다.
