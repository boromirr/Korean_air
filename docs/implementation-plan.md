# 1차 조사 및 단일 노선 수집 계획

요청 범위: 전체 서비스 중 작업 순서 1~5단계. ICN → JFK, 편도, 미래 한 달의 실제 비로그인 공개 현황 JSON을 확인하기 전에는 웹서비스 UI·DB·카카오톡·배포로 진행하지 않는다.

1. 작업 폴더와 Git 상태 확인: 폴더는 비어 있으며 Git 저장소가 아니었음. 기존 코드 및 사용자 변경 없음.
2. 계획 및 최소 TypeScript/Playwright 실행 환경 준비. 민감 파일을 Git에서 제외.
3. 새 비로그인 Playwright 브라우저에서 공식 페이지를 방문. 실제 DOM, 사용 흐름, 요청 메타데이터, 쿠키 이름/속성만 조사. 쿠키 값·인증정보는 기록하지 않음.
4. 확인한 내용과 미확인 사항, robots.txt/이용약관, 수집 방식 선택 근거를 `docs/koreanair-public-flow.md`에 기록.
5. 관찰된 DOM만 사용하는 ICN → JFK 한 달 수집기 구현. 실제 출력과 날짜 수·보너스/승급·null 좌석 수를 검증.

CAPTCHA, 접속 차단 또는 보안 확인은 우회하거나 무한 재시도하지 않는다. 차단 시 진단을 보존하고 실제 수집 성공으로 처리하지 않는다. 확인하지 못한 DOM/API 선택자는 추측해서 구현하지 않는다. 수집 실패를 좌석 없음으로 변환하지 않는다.

조사 중 HTML/스크린샷 등 원시 자료는 Git에서 제외한 `artifacts/`에만 저장한다. JSON 결과는 `data/`에 저장한다. 공식 데이터 갱신 시각이 공개되지 않으면 `sourceUpdatedAt: null`, 정확한 수량이 공개되지 않으면 `availableSeatCount: null`로 유지한다.

## 실행 완료 기록

1~5단계 범위의 실제 수집 성공. `2027-04` ICN → JFK 편도 30일을 추출하고 화면 및 브라우저의 월간 응답과 대조했다. 추가 사용자 지시에 따라 Network 응답의 좌석 수 필드도 조사했으나 boolean 표시만 있었다. 날짜별 반복 클릭 없이 월 전체를 한 번에 파싱한다. [실행 검증 결과](verification-results.md)와 [조사 문서](koreanair-public-flow.md)를 참고한다. 사용자가 JSON을 확인하기 전에는 카카오톡·배포로 진행하지 않는다.
