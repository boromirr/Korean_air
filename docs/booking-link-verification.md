# 마일리지 보기 URL 검수

검수일: 2026-09-07. 사용자가 원한 동작은 검색 결과 행의 노선·날짜·좌석 조건으로 바로 이동하는 링크다.

## 실제 확인

1. `https://www.koreanair.com/booking/book-and-manage/award-seat-availability`는 공통 공개 조회 진입 화면이다. 결과 행마다 같은 URL을 넣어도 해당 항공편이 자동 선택되지 않는다.
2. 새 비로그인 Playwright Chrome에서 ICN → SIN / 편도 / 2026년 11월을 조회하고 11월 4일 선택 → `항공권 예매하기` → `보너스 항공권`을 클릭했다.
3. `마일리지 사용 항목 선택` 모달 다음에 로그인 모달이 열렸고 주소는 공통 공개 조회 URL 그대로였다. 이 과정에서 노선/날짜가 포함된 공유 URL은 생성되지 않았다. 로그인은 진행하지 않았다.
4. 공식 사이트맵 및 마일리지 안내에 있는 `https://www.koreanair.com/booking/search?bookingType=A&gnb=true`를 별도의 새 비로그인 BrowserContext에서 열었다. 실제로 `https://www.koreanair.com/login`으로 이동하며 로그인 화면이 나타났다. 로그인 후 조건 유지 여부는 미검증이다.

## 공식 출처

- https://www.koreanair.com/contents/footer/others/sitemap
- https://www.koreanair.com/contents/booking/reservation-guide/how-to-book/mileage-booking-guide/award-ticket
- https://www.koreanair.com/contents/skypass/use-miles/award-ticket/guide

공식 안내에서 `bookingType=A&tripType=RT` 및 `bookingType=A&gnb=true` 링크는 확인했다. 노선·날짜·프레스티지 조건을 전달하는 공개 딥링크 규격은 확인하지 못했다. 미확인 파라미터를 추가하거나 브라우저 쿠키·세션을 URL에 넣지 않는다.

## 결과 표시 원칙

- 공통 공개 조회 URL을 노선별 상세 결과 링크처럼 표시하지 않는다.
- 공식 마일리지 예매 진입 링크에는 로그인 필요 및 노선·날짜 자동 입력 미검증을 명확히 안내한다.
- 저장한 증거 이미지를 제공할 때는 `확인한 결과 화면`이라고 표시하고 실시간 공식 결과 URL과 혼동하지 않는다.
- 노선·날짜별 직행 공식 URL 지원 여부는 미확인이다. 확인하지 못한 사실을 지원 불가능이라는 단정으로 확대하지 않는다.

## 사용자 직접 로그인 후 추가 검증 (2026-09-07)

사용자가 열린 Chrome에서 직접 로그인했다. 비밀번호·쿠키·로그인 세션을 파일로 저장하거나 공유하지 않고, 같은 BrowserContext에서 공개 달력의 ICN → SIN / 2026-11-04 / 편도 조건을 선택했다.

| 시험 | 실제 결과 |
|---|---|
| 로그인한 탭에서 날짜 선택 → 항공권 예매하기 → 보너스 항공권 | `/booking/search?bookingType=A&gnb=true`로 이동. UI에 ICN, SIN, 11월 04일, 편도 유지. 좌석 등급은 공식 화면에서 모든 클래스이며 비즈니스만 선택된 상태라고 주장하지 않음. |
| 항공편 검색 | `/booking/select-award-flight/departure`로 이동. 쿼리 파라미터 없음. 여정은 표시됐으나 목록에 정상 처리 실패 안내가 나옴. 실제 재고·운임·예약 가능 여부는 이 실행으로 확정하지 못함. |
| **로그인 쿠키를 공유하는 독립 새 탭**에서 위 결과 URL만 열기 | 홈페이지 `/`로 이동. 해당 여정 결과가 재현되지 않음. |
| 같은 새 탭에서 공통 마일리지 예매 URL 열기 | 마일리지 예매 탭은 선택되나, 왕복 / SEL / 도착지 미선택 / 날짜 미선택으로 초기화. |

**이 두 공식 URL은 로그인되어 있어도 특정 여정의 바로가기로 동작하지 않음을 실제 확인했다.** 다른 미확인 공식 딥링크 규격까지 지원 불가라고 단정하지는 않는다. 같은 탭의 선택 과정을 거치며 전달되는 상태와 URL 자체의 정보를 구분해야 하며, 그 상태가 어떤 저장소에 보관되는지는 조사하지 않았다.

이 요구를 구현하려면 확인된 대안은 로그인된 브라우저의 같은 작업 탭에서 노선·날짜를 자동 입력하고 공식 조회를 실행하는 방식이다. 버튼의 기능 설명은 `해당 조건으로 자동 검색`이 적합하다. 실제 예약 확정이나 결제를 자동 진행하지 않는다.

첫 처리 오류 후 공식 UI의 `항공편 검색`을 한 번 재시도하면서 상태 코드만 관찰했다. 브라우저가 호출한 `/api/ap/booking/avail/awardAvailability`가 **HTTP 403**을 반환했다. 이 시점에서 추가 조회를 중단했다. 호출 재현, 쿠키 변경, 브라우저 지문 변경 등 우회를 수행하지 않았다. 따라서 로그인된 자동 검색의 실시간 좌석 목록 표시 성공까지 검증한 것은 아니다. 접근 거부의 원인이 계정·세션·자동화 정책 중 무엇인지는 확인되지 않았다. 화면의 `0 마일 + 0.00`은 처리 실패 화면이므로 실제 마일리지 비용으로 해석하지 않는다.

## 로컬 앱의 공개 달력 자동 입력 (2026-09-07)

로컬 결과의 `선택한 날짜로 대한항공 열기` 버튼은 `/api/open-airline`으로 선택한 노선·여정 종류·좌석 등급·가는 날·오는 날을 전달한다. 로컬 프로그램은 별도의 새 비로그인 Chrome에서 공개 달력의 정상 UI를 입력한다. 공통 URL만으로 선택 조건을 전달하거나 사용자의 기존 로그인 세션을 복제하는 기능이 아니다.

첫 화면에는 출발·도착 공항, 편도/왕복, 가는 달·오는 달을 입력한다. 조회 달력에서는 보너스 필터만 선택한 좌석 등급으로 좁힌 뒤 날짜를 선택한다. 왕복은 `가는 날`, `오는 날` 탭을 각각 처리한다. 입력 완료 후 창을 유지하고 자동 동작을 끝낸다. 로그인·마일리지 예매·결제 화면은 이 기능의 자동 처리 범위에 포함하지 않는다.

실제 공개 UI에서 확인한 주의점:

- 같은 달 왕복은 월을 두 번 선택해야 한다. 첫 클릭 후 월 버튼의 접근성 이름에 `선택됨 ,가는 달,`이 붙는다.
- 필터는 숨겨진 체크박스와 연결된 표시 라벨을 클릭한다. 작은 화면의 `선택 완료`가 보이면 누르고, 큰 화면에서는 `닫기`로 돌아온 뒤 실제 달력의 표식으로 적용 여부를 확인한다. 가는 편과 오는 편의 필터가 따로 유지된다.
- 작은 화면에서는 날짜를 클릭한 후 항공편별 상세 팝업의 `해당 날짜 선택`을 눌러 확정한다. 왕복 가는 날짜 확정 후 오는 날 탭으로 전환된다.
- 큰 화면에서는 날짜 클릭으로 바로 선택된다. 왕복 최초 선택에서 오는 날 탭으로 자동 전환되는 경우와, 이미 선택한 일정을 변경하여 가는 날 탭이 유지되는 경우를 모두 확인했다. 실제 탭 상태에 따라 전환하며 하단에 표시된 선택 날짜로 확정 여부를 판단한다.
- 완료 여부는 달력의 노선·월·선택 날짜 표시를 확인한다. 공개 보너스 표시는 실제 예약 가능 여부나 잔여 좌석 수의 확정이 아니다.

로컬 서버는 입력한 날짜의 실존 여부와 조회 월 일치, 왕복 날짜 순서를 검사한다. 새 조회와 자동 입력은 동시에 실행되지 않는다. 접근 제한이나 보안 확인 시 처리를 중단하고 기존 조회 결과를 보존한다.
