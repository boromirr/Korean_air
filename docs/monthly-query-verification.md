SAS의 최신 접속 제한 이후 추가 실조회를 하지 않았다. 403·429는 접속 제한으로 중단하며 재시도하지 않는다. 일반적인 검색 실패·시간 초과만 한 차례 새 검색으로 재확인한다. 조회 중단 시 이 작업이 연 탭을 닫고 로그인 창은 유지한다.

SAS는 요청한 노선·날짜에 해당하는 공식 항공편 응답을 받은 뒤 화면 결과를 읽는다. 임시로 보이는 빈 결과를 완료로 판단하지 않는다. 스타얼라이언스는 같은 탭에서 공식 여정 변경 기능을 사용하고 새로운 조회 응답 및 결과 날짜를 대조한다.

자동 검사: 프로그램별 월 단위 작업 전달, 역방향 노선과 스카이팀 기준일 보존, 중단·제한·부분 결과 처리, 임시 빈 화면 배제, 다른 날짜 결과 거부를 검사했다. 자동 검사는 항공사 응답을 대체한 자료를 사용하며 실사이트의 속도나 월간 조회 기능을 보장하지 않는다.

상단 버튼 정리 후 사용자 요청으로 현재 실행 중인 앱에서 재검증했다. 결과는 같은 노선(ICN→NRT), 2027년 5월, 전체 좌석 등급을 기준으로 측정한다. 스카이팀은 왕복 전용이어서 가는 달 5월과 오는 달 6월(총 61일)을 사용한다. 각 프로그램은 순서대로 실행하여 항공사 작업끼리 겹치지 않도록 했다.

대한항공은 앱 응답의 `cached: false`와 저장된 `dates` 31개를 확인했다. 아시아나·스타얼라이언스도 날짜 중복 없이 31개를 확인했다. 속도는 시작 요청부터 완료 상태를 수신할 때까지이며, 상태 확인 간격으로 최대 약 2초의 차이가 생길 수 있다. 로그인 확인 시간은 별도다.

이번 검증의 결론: 다섯 프로그램 모두를 대한항공처럼 빠른 월간 일괄 조회로 제공한다는 요구는 여전히 충족되지 않았다. 시연 시 월간 일괄 조회 성공으로 설명할 수 있는 것은 현재 대한항공과 아시아나다. 한 번의 성공 측정은 다른 노선·월의 속도를 보장하지 않는다.

SAS의 제한 표시는 서버가 보존한 기존 상태를 포함한다. 이번에 항공사에 새 조회를 보내 제한 해제 여부를 시험한 것은 아니며, 최신 월간 완료 시간은 확인하지 못했다. 스카이팀의 61/61은 처리 수이지 좌석 확인 성공 수가 아니다. 오는 편 30일은 좌석 없음으로 판단할 수 없다.
